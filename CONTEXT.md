# Human-Agent Collaborative Software Engineering

This context describes how humans and different kinds of agents form project teams, agree on specifications, and carry out traceable software work.

## Team

**Human**:
A real person who participates in a project and may create, cultivate, sponsor, review, or approve the work of agents.
_Avoid_: HumanAgent, human worker

**Agent Actor**:
Any non-human project participant that may receive Work Items and produce Executions, including Digital Employees, System-Generated Agents, and Private Agents.
_Avoid_: Model, session, executor

**Digital Employee**:
A formally published, capability-fixed Agent Actor with verifiable provenance that can be reused across projects through immutable releases.
_Avoid_: All agents, System-Generated Agent, Private Agent

**System-Generated Agent**:
A project-scoped Agent Actor generated by the system for a current need and treated as a Candidate until qualified or granted a restricted trial.
_Avoid_: Digital Employee, automatically trusted agent

**Private Agent**:
A Human-controlled and cultivated Agent Actor that may be proposed for project use without being a formally published Digital Employee.
_Avoid_: Digital Employee, project-owned agent

**Creator**:
The Human who originally creates or initiates an agent; creation does not by itself grant project authority.
_Avoid_: Owner

**Cultivator**:
A Human responsible for developing an agent's instructions, skills, working style, and reusable capabilities over time.
_Avoid_: Trainer, prompt owner

**Custodian**:
The Human currently authorized to manage a Digital Employee's versions and portability independent of any one project.
_Avoid_: Owner, administrator

**Publisher**:
The Human or organization authorized to issue new immutable releases of a Digital Employee for projects to adopt.
_Avoid_: Project Sponsor, executor provider

**Project Sponsor**:
The Human accountable for an Agent Actor's requested role and permissions within a particular project.
_Avoid_: Global owner

**Agent Membership**:
An Agent Actor's project-specific participation, including its source type, approved role, permissions, sponsor, configuration snapshot, and trust status.
_Avoid_: Agent identity, execution

## Capability and continuity

**Digital Employee Release**:
An immutable published version of a Digital Employee's instructions, skills, memory policy, and declared capabilities that projects may pin and explicitly upgrade.
_Avoid_: Latest agent config, mutable profile, runtime session

**Upgrade Proposal**:
A request for an Agent Membership to adopt a newer Digital Employee Release after project-specific compatibility, permission, and capability review.
_Avoid_: Automatic update, live mutation

**Improvement Proposal**:
A project-originated, privacy-reviewed suggestion that a Publisher may use to cultivate and validate a future Digital Employee Release.
_Avoid_: Automatic memory write-back, project memory export

**Security Revocation**:
A Publisher-issued declaration that a Digital Employee Release must not start new Executions and that its active Executions require Human review.
_Avoid_: Silent patch, history deletion

**Capability Evidence**:
Externally observable evidence that supports an Agent Actor's capability claim, produced through verification or Human review rather than self-assessment.
_Avoid_: Capability label, self-rating

**Capability Gap**:
A required Work Item capability not covered by the Humans and Agent Memberships currently selected for the project; it prompts Human staffing action rather than automatic assignment.
_Avoid_: Agent ranking, automatic hire

**Portable Memory Package**:
An explicitly approved subset of a Digital Employee's reusable memory that may cross project boundaries without carrying private project context or credentials.
_Avoid_: Full memory export, conversation history

## Project work

**Traceable Operation**:
A platform-mediated action that can affect project state, permissions, execution, or shared engineering results and is recorded with its actor, target, outcome, and causal context. Traceability does not imply that the action is reversible.
_Avoid_: Plain log line, automatically reversible action

**Recorded Consensus**:
The project decision registered after Humans reach agreement outside the platform; the platform preserves the result and recorder but does not claim to observe the discussion itself.
_Avoid_: Platform vote, verified unanimity

**Specification**:
A versioned statement of project intent, scope, constraints, and acceptance criteria that becomes authoritative only after the required review.
_Avoid_: Prompt, informal requirements

**Work Item**:
A traceable unit of project work derived from an effective Specification and carrying its own goal, acceptance criteria, dependencies, risk, and required capabilities.
_Avoid_: Prompt, agent session

**Exploration Work Item**:
A traceable, bounded investigation used when the project needs evidence before it can define or revise a Specification; its result does not enter shared product code without subsequent specified work.
_Avoid_: Untracked experiment, implementation shortcut

**Execution**:
One attempt by a Human or Agent Actor to perform a Work Item using a fixed configuration and project context.
_Avoid_: Work Item, Agent Actor, chat

**Workspace Checkpoint**:
A restorable snapshot of managed workspace state captured at a platform-controlled Execution boundary, excluding agent-internal state and unmanaged external side effects.
_Avoid_: Audit event, guaranteed rollback of external systems

**Execution Checkpoint**:
An atomic association of a Workspace Checkpoint, an opaque Kernel Checkpoint Reference, and the project and input versions from the same stable Execution boundary.
_Avoid_: Workspace-only snapshot, timestamp correlation

**Kernel Checkpoint Reference**:
An opaque reference produced and later consumed by an Executor Adapter to return its Kernel to an Execution Checkpoint without exposing agent-internal state to the platform.
_Avoid_: Parsed agent reasoning, platform-owned session state

**Execution Branch**:
A new Execution created from an earlier Execution Checkpoint with revised platform inputs; the prior Execution remains available for comparison and traceability.
_Avoid_: History rewrite, log deletion, shared-project rollback

**Reconstructed Branch**:
A new Execution started from a Workspace Checkpoint when the Kernel cannot restore an exact internal checkpoint; it must not be represented as an exact rewind.
_Avoid_: Exact rewind, resumed Execution
